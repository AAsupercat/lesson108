# CP_Mod 运行逻辑梳理

## 整体概述
程序展示典型的生产者-消费者模型：`BlockingQueue` 负责在线程间传递任务，并通过互斥锁与条件变量控制同步；`Productor` 连续写入任务，`Consumer` 持续读取任务，主线程负责创建并等待两个子线程。

## 核心组件
1. `BlockingQueue<T>`
   - 维护有界队列，默认容量 10。
   - `push` 在队列满时等待，达到高水位线后通知消费者。
   - `pop` 在队列空时等待，低于低水位线后通知生产者。
2. `Productor`
   - 使用全局递增整数 `mydata` 作为任务。
   - 每次调用 `push`，打印日志并 `sleep(2)` 模拟生产耗时。
3. `Consumer`
   - 调用 `pop` 获取任务，并打印接收日志。

## 运行流程
1. `main` 创建共享 `BlockingQueue<int>`，随后生成消费者与生产者线程。
2. 生产者循环：
   - 若队列已满则阻塞，待消费者唤醒。
   - 将当前 `mydata` 入队、打印日志、递增 `mydata`、休眠 2 秒。
3. 消费者循环：
   - 若队列为空则阻塞，待生产者唤醒。
   - 将取出的任务打印展示。
4. 主线程通过 `pthread_join` 保持进程持续运行；两个子线程均为无限循环，需外部手段终止。

## 关键特性
- **背压控制**：通过高/低水位线控制唤醒时机，避免频繁唤醒。
- **线程安全**：所有队列操作都在同一个互斥锁保护下完成。
- **可观测性**：生产/消费日志可直观验证队列运行状态与阻塞行为。
